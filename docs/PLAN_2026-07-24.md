## 3. Stream A — mdqc agent changes (v0.5.0)

Ordered by priority. Each item: what, where, production-grade detail, test.

### 3.1 Configurable `.skyr` path  ★ unblocks Stoyan

**What:** stop hardcoding the report filename.

**Where:** `SkylineConfig` (`config/schema.py`) + `extractor/__init__.py:169`.

**Design:**
```toml
[skyline]
report_skyr_path = "auto"   # "auto" = methods_dir()/MD_QC_Report.skyr (back-compat)
                            # or an absolute path to any .skyr
```
- `"auto"` (default) preserves current behaviour — no migration needed for existing installs.
- An explicit path is used verbatim; if it doesn't exist, log a clear `ERROR` (not a silent fallback) naming the path we looked for, and fail the extraction with that message. Silent fallback is exactly what confused Stoyan with the column override.

**Test:** unit test that an explicit path resolves; that a missing explicit path produces a named error; that `"auto"` resolves to the methods dir.

### 3.2 Collapse transitions → peptides  ★ core data-model fix

**What:** emit one `TargetMetric` per peptide, not per transition.

**Where:** new post-parse step in `extractor/report.py` (after `parse_skyline_csv` builds per-row metrics), gated by config so it's reversible.

**Design — the universal collapse rule** (chosen because it's robust to both the "repeats identically" and "per-fragment" cases without special-casing individual columns):

Group rows by `(protein_name, peptide_modified_sequence)`. For the emitted peptide-level `TargetMetric`:
- **Every numeric field and numeric `extra_metric`** → **mean of non-null / non-NaN values** in the group. Mean of N identical values = that value (handles Total Area, RT, etc. that repeat), and mean of the fragment-level values handles Skewness/Kurtosis correctly. This is the key insight — one rule covers everything.
- **String fields** (peptide_sequence, protein_name, Note) → first non-null.
- `detected` → `any(detected)` across the group.
- `target_id` → recomputed from the peptide+mz (stable).

Guard: treat the string `"NaN"` (Skyline's literal for empty Skewness/Kurtosis) as null in `_get_float` — **verify the current `_NA_TOKENS` set includes `"nan"`** (it does: `_NA_TOKENS` has `"nan"`), so `_get_float("NaN")` already returns `None`. The mean-of-non-null then naturally skips them.

```toml
[skyline]
collapse_transitions_to_peptides = true   # default on
```

**Why config-gated:** if a future report is genuinely per-peptide already, or someone wants transition-level detail, they flip it off. Also lets us ship it safely — if the collapse misbehaves on an edge case, the operator has an escape hatch.

**Test:** feed the real `MD_QC_Report_20260723.csv` fixture → assert 8 output metrics; assert `RISGLIYEETR` Skewness == mean(-0.454, -0.372, -0.49); assert Total Area == 1418427 (not summed, not duplicated); assert `Non_reactive_Targets` peptides all present.

### 3.3 Real acquisition timestamp from Skyline  ★ unblocks ordering + date filter

**What:** use Skyline's `Acquired Time` (read from the raw-file header) as `acquisition_time`, replacing file mtime.

**Where:** `report.py` (extract the value), `types.py` (`ExtractionResult.acquired_time`), `extractor/__init__.py` (set it), `spool/store.py:158` (prefer it).

**Design:**
- Add `acquired_time: str | None` and `modified_time: str | None` to `ExtractionResult`.
- In `parse_skyline_csv`, capture `Acquired Time` from the first data row (identical across rows). Parse Skyline's locale format — the sample is `"7/22/2026 2:44:30 AM"` (US `M/D/YYYY h:mm:ss AM/PM`). **Robustness:** try a short list of formats (`%m/%d/%Y %I:%M:%S %p`, ISO-8601, `%d/%m/%Y %H:%M:%S`), and if all fail, log a `WARNING` and leave it `None` (falling back to mtime). Skyline's output is locale-dependent, so this parser must not hard-fail.
- Emit as ISO-8601 UTC. **Caveat:** Skyline's AcquiredTime has no timezone. Treat it as instrument-local and record it **without** forcing a UTC offset (store the naive local time as-is, tagged as local) — or, decision for Giuseppe: does the platform want naive-local or UTC? The raw-file header time is what the operator recognizes ("the run at 2:44 AM"), so naive-local is probably right. **Flag as an open question (§7).**
- `spool.enqueue`: `acquisition_time = extraction.acquired_time or _file_acquisition_time(raw_file_path)`.

**Test:** parse a CSV with a known Acquired Time → assert the ISO string; assert fallback to mtime when the column is absent or unparseable.

### 3.4 `Note` column as a string passthrough

**What:** surface `Peptide Note` (free-text) in the payload.

**Where:** `report.py` — currently `extra_metrics` only accepts numeric values (non-numeric are dropped with a debug log). Add a parallel `extra_string_metrics: dict[str,str]` on `TargetMetric`, or a dedicated `note: str | None` field.

**Design:** a dedicated `note: str | None` on `TargetMetric` is cleaner than loosening `extra_metrics` (keeps the numeric contract intact). Map the `Peptide.Peptide.Note` / `Peptide Note` column to it via the alias table.

**Test:** CSV with a Note value → assert it lands on the peptide's `note`.

### 3.5 Fix the stale-override footgun (the `mass_error_ppm` warning)

**What Stoyan hit:** his `config.toml` still has `[skyline.report_columns] mass_error_ppm = "Mass Error PPM"` from an earlier report. The new `.skyr` renamed that column to `Average Mass Error PPM`. The override fails → `WARNING ... falling back to defaults`. The **default alias table already contains `"average mass error ppm"`**, so the fallback *does* map it correctly — but the warning made Stoyan think it was broken, and the payload he inspected showed `mass_error_ppm: 0.0` (which may be a legitimately near-zero value on that peptide, not a failure).

**Two fixes:**
1. **Config hygiene:** tell Stoyan to delete the now-stale `mass_error_ppm` override line — the alias table handles the new column automatically. (Docs/email, not code.)
2. **Make the fallback legible:** when an override column isn't found but the alias table *does* resolve the canonical from another column, upgrade the log from a bare "falling back to defaults" to `"override column 'X' not found; resolved 'mass_error_ppm' from 'Average Mass Error PPM' via built-in alias instead"`. Silent-but-correct is worse than loud-and-correct here — Stoyan needs to trust what it did.

**Test:** override points at a missing column, alias resolves a different present column → assert the canonical is populated AND the log names the column it actually used.

### 3.6 Digest-efficiency as an emitted metric

**What:** compute `cleaved / (cleaved + miss-cleaved)` and put it in the payload.

**Where:** `extractor/__init__.py` `_run_metrics`, using the existing `compute_digest_efficiency()` (already correct: shorter sequence = cleaved = numerator).

**Design:** add `digest_efficiency_pct: float | None` to `RunMetrics`. Compute post-collapse (needs peptide-level areas). Emit as a percentage 0–100. The color thresholds (>80/70–80/<60) are a **platform display concern** — the agent emits the number, the platform colors it. Don't hardcode thresholds in the agent.

**Test:** the two-peptide fixture → assert the ratio; assert `None` when the miss-cleavage pair is absent.

Add enum members `EB` and `PB`; add classifier patterns (`_eb_`, `_pb_`, and whatever Stoyan's filenames use — confirm the exact tokens; the CSV shows `eb_qc` in names). Keep `BLANK` for generic/unknown blanks.

## 5. The system-suitability / local-optimum architecture (the big idea)

This is the conceptual core and it deserves its own section because it reshapes the product. It also spans both the agent and the platform, and the seam matters.

### 5.1 The concept

- On **installation** (or after a column change / front-end clean / major service), the customer or field engineer runs **15–20 SSC0** (system suitability control — a QCB-equivalent digest at 50 ng). This set defines the **local optimum**: how *this* LC-MS + Lupo performs *right now*.
- Every subsequent QC run is expressed as a **ratio to that baseline**, not an absolute value:
  - **QC B / SSC0 ≈ 1.0** — both 50 ng, both bypass digestion variability → this ratio tracks **LC-MS health**.
  - **QC A / SSC0 ≈ a fixed multiple** (QC A is 1 µg lysate, ~300 ng on column vs 50 ng → Stoyan est. ~6× on column; exact ratio TBD empirically) → this ratio tracks **digestion-workflow health**.
- Retention times are baselined too: the 15–20 SSC0 runs give a **mean expected RT per peptide per SPD**, and drift is measured against that (not against a hardcoded spec, which Stoyan flagged as dangerous because columns vary).
- **Baselines are resettable and versioned in time.** Column change → new SSC0 set → new local optimum. The customer can see baselines over time and choose which to reference against.

### 5.2 Why this lives on the platform, not the agent

Giuseppe's key point, and it's correct: **the agent is open-source and customer-editable — you can't lock down a "gold standard" flag in the JSON.** Anyone can edit it. So the baseline can't be a trustworthy agent-side hardcode.

Resolution reached on the call (Stoyan's preferred model): **the baseline is set on the platform by selecting a date-range of SSC0 runs** ("scroll across the time range where you recorded your SSC0, say *this is my reference dataset*, everything else compares to it"). The platform stores the baseline as a record on the customer's account. The agent's *only* responsibilities are:

1. **Tag `control_type` reliably** (SSC0 vs QC_A vs QC_B vs EB vs PB) — from the filename, already done.
2. **Emit real acquisition timestamps** (§3.3) — so the platform can define the baseline date-range accurately.
3. **Emit clean per-peptide values** (§3.2) — so per-peptide baseline medians are meaningful.

That's it. The agent gets *simpler* under this model, not more complex. No "engineer mode toggle", no gold-standard flag in the JSON (both were floated and set aside as un-lockable).

### 5.3 What the platform builds (for Giuseppe)

- A **Baseline** entity per `(instrument, SPD, control_type=SSC0)`: `id`, `created_at`, `label`, `date_range`, `n_runs`, `per_peptide_median: {peptide → {area, rt, …}}`, `notes` ("after column change" etc.).
- UI to **nominate a baseline** by selecting an SSC0 date-range on the longitudinal plot.
- **Ratio panels**: a second traffic-light row showing QC A / SSC0 and QC B / SSC0, and per-peptide RT-vs-baseline. This becomes the **default operator view** — the "is the LC-MS OK? is the Lupo OK?" answer.
- **Split calculation from visualization** (Giuseppe's idea): compute stats over a wide window (e.g. 90 days) but let the user zoom the view to 7 days without changing the baseline. This directly addresses the "the 2SD boundary moves when I filter" problem.
- **Fixed-threshold mode**: per-metric absolute windows (e.g. ppm < 3 = green) as an alternative to relative 2SD.

### 5.4 The calibration data (Stoyan's dilution series)

Everything above needs **thresholds**, and thresholds need data. Stoyan's dilution series (QCB 100%→20%, 8 replicates each, across Exploris/Astral/timsTOF/triple-quads, plus ~16 SSC0 at 100%) answers: *what does a 20% signal drop look like in each metric on each platform?* That defines the green/yellow/red bands. Until it lands, thresholds are placeholders. **This is the gating dependency for making the traffic light trustworthy** — build the mechanism now, calibrate when the data arrives.
