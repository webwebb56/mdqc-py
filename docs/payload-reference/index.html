Every field in a QC payload

One JSON file per run. This is what each field means, whether it was measured or derived, and for the derived ones, the exact calculation. Example values are from payload_02_qcb_healthy.json in the repo — a synthetic reference payload, modelled on the Evosep panel at 200 SPD. Real values will differ; the field names and calculations will not.

schema_version 1.2
The design principle

Every raw input is emitted alongside every derived flag. Nothing is reduced to a verdict you cannot reconstruct. Thresholds are provisional and being recalibrated across platforms, so the platform must be able to re-derive any judgement under different numbers — which is why thresholds_applied travels with every run rather than being looked up server-side.

Timestamps — read this before writing a parser

All three timestamp fields (timestamp, run.acquisition_time, baseline_context.created_at) are ISO 8601 and always carry an explicit offset, so they are never ambiguous and never naive. Two things to know:

The offset is written +00:00, not Z. The two mean the same thing — Z is "Zulu", the ISO 8601 / RFC 3339 shorthand for a zero UTC offset — but they are different bytes, and a strict parser or a string comparison written for one will not accept the other.

acquisition_time is not guaranteed to be UTC. Where the Skyline report carries an AcquiredTime column, the agent attaches the instrument PC's local offset — deliberately, so the wall clock matches what the operator saw. An instrument in Copenhagen emits +02:00; one in Melbourne emits +10:00. Sorting and comparison are safe because the offsets are explicit, but grouping by calendar day is not until you decide whose day you mean.

Display names differ from stored values

Evosep renamed the controls in the August 2026 SOP review. The payload keeps the original control_type values because the platform already consumes them — renaming those is a schema change, not a documentation one. Apply this mapping wherever control type is shown to a user:

QC_A → display PC (process control)  ·  QC_B → display SSC (system suitability control)  ·  SSC0 → display SSC-gold

Thresholdscomparison_metrics.thresholds_applied

Editable per installation in the agent's Settings page, because Evosep asked to be able to recalibrate in the field without a release. All are percentages.

FieldDefaultWhat it gates
rt_deviation_pct_max2.0Sets rt_outside_threshold. Being replaced by absolute seconds where no baseline exists.
dot_product_deviation_pct_max5.0Agreement expected for a correctly identified target.
dot_product_deviation_pct_suspect10.0Corroborating arm of the mis-extraction conjunction.
peak_area_deviation_pct_suspect30.0Alternative corroborating arm of the same conjunction.
peak_area_deviation_pct_warn15.0Warn band. Raised from 10% at Evosep's instruction — late-eluting targets under-estimate recovery loss and were warning falsely.
peak_area_deviation_pct_fail25.0Fail band. Roughly a 50% reduction in material reaching the column.
A consequence worth knowing

At a 15% warn band, Evosep's 75%-load condition medians at −9.5% deviation and produces no warning at all — a quarter of the material missing, silently. It cleared the old 10% band by half a point too. The expected resolution is per-peptide scoring, where two or three mid-gradient peptides carry the recovery estimate and early and late ones report qualitatively on chromatography.
