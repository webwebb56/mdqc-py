### §4 Definitions

**You wrote:** *"SSC0 and QC B are identical i.e. k562 digest at 50ng on Evotip
loaded by the Lupo. The difference [is] how and when they are used i.e. the
SSC0 to set the reference baseline, QCB to measure LCMS performance across

This was the most substantive correction and I had it wrong. The draft
distinguished the two by handling, implying a material difference that does not
exist. Both definitions are rewritten:

- **SSC₀** — a standard K562 peptide digest, 50 ng on Evotip, loaded by the
  Lupo. Used to **set the reference baseline**.
- **QC B** — **materially identical to SSC₀**. The difference is how and when
  each is used: SSC₀ sets the reference, QC B measures against it over time.

**QC A** now also states its load explicitly — roughly 1 µg, about six times
SSC₀ on column. That figure turned out to matter beyond the definition; see
Part 2.

One knock-on correction you did not flag: §B4 still said QC B and SSC₀ *"receive
equivalent loads"*. Now *"are the same material at the same load"*, to match.

**You also wrote:** *"a few more definitions that can be added on .skyr metrics

document as pending, awaiting the final metric list.

### Figure 12 — Resulting baseline

**You wrote:** *"The CV value is for the median area? So there should be one for
RT also but instead of CV better to stdev (in seconds)"*

**Product change.** The baseline table now reads:

| Peptide | Median area | Area CV% | Median RT (min) | RT sd (s) | n |
|---|---|---|---|---|---|

The area column is renamed **Area CV%** so it is unambiguous, and retention-time
spread is reported as **standard deviation in seconds**. Your reasoning holds
beyond convention: a percentage of an absolute retention time is not comparable
between peptides eluting at different points in the gradient.

The demonstration data also had retention-time spread near zero, which was not
plausible. It now sits at a few tenths of a second.

### §B6 Escalation

Your seven annotations are all incorporated, and the table is rewritten around
them rather than patched:

| Observation | Domain | Action |
|---|---|---|
| QC B and SSC₀ down; QC A down proportionally | LC-MS | MS-specific sensitivity tests per vendor; Evosep troubleshooting guide |
| QC B and SSC₀ steady, but QC A recovery peptides down and/or digest efficiency lower | Sample preparation | Review digestion and Evotip loading; Lupo troubleshooting guide |
| **QC A digest efficiency down** | Sample preparation | **Check kit expiry date**, then digestion conditions |
| RT drifting across all peptides, **as well as FWHM increase** | Chromatography | Column age and pressure; Evosep troubleshooting guide; re-baseline after a column change |
| Replicate variability high within one preparation run | Sample preparation | **Potential Evotip loading issue** — Lupo troubleshooting guide |
| One peptide flagged as extraction problem | Data processing | Not an instrument fault — report to MD |
| Runs not appearing at all | Configuration | Check filenames first |

Both troubleshooting-guide links point to
<https://www.evosep.com/support/troubleshooting/> as you supplied.

## Part 2 — One thing your comments led me to fix in the agent

Your note that QC A runs at roughly six times the SSC₀ load prompted me to check
what the agent does with that.

It was scoring QC A against thresholds that measure deviation from a ratio of
1.0 — so **every QC A run came back "fail"**. The verdict is now withheld for
control types whose expected ratio is not 1.0, with the payload carrying a note
saying why, so a withheld verdict is distinguishable from missing data. The
underlying ratio is still emitted, so nothing is lost.

This matches your own observation that the decision matrix is stated for QC B
and that the expected SSC₀ : QC A ratio is still to be determined. Once you have
that figure we can score QC A properly.
