1. Purpose and scope

This document describes how to install, commission and operate MD QC — a monitoring system that watches an LC-MS instrument's acquisition folder, extracts quality-control measurements from every QC injection, and tracks them over time against a reference established on that specific instrument.

It covers two components:

  • The MD QC agent — a background service installed on the instrument PC. Detects new acquisitions, runs a targeted Skyline extraction, and writes a structured result for each run.
  • The Mass Dynamics platform — the web application where results from one or many instruments are reviewed longitudinally.

In scope

Installation on a Windows instrument PC; configuration for a single instrument; establishing an instrument-specific reference (the gold standard); routine interpretation; troubleshooting; and the data-handling questions an IT reviewer will ask.

Not in scope

Operation of the Evosep Lupo, Evosep Eno or the mass spectrometer itself — see the respective Evosep manuals. Preparation of QC A, QC B and SSC₀ samples — see the Evokit instructions. Design of the Skyline method.

3. System overview

The agent runs continuously on the instrument PC and requires no operator action once configured.

Instrument acquires a QC injection
        │
        ▼
  Acquisition folder            ← the agent watches this
        │
        ▼
  Agent waits for the file to stop changing   (default 60 s)
        │
        ▼
  Classify from filename        → QC A / QC B / SSC0 / blank / sample
        │
        ▼
  Skyline extraction            → per-peptide measurements
        │
        ▼
  Compare against the gold-standard baseline for this instrument + SPD
        │
        ▼
  Result written locally, and uploaded to Mass Dynamics if configured

The central idea is comparison against the instrument's own reference, not against a universal specification. At installation, a set of SSC₀ injections defines how this particular LC-MS and sample-preparation system performs when healthy. Every later QC run is expressed as a ratio to that reference. This is what makes the same thresholds meaningful across different instruments, and it is why §A9 is a required commissioning step rather than an optional extra.

Local operation

The agent works fully offline. A cloud connection adds longitudinal review across instruments and over time, but is not required for the monitoring loop. Where cloud upload is not permitted, follow Part A but skip §A8, and see §C5 for what this changes.

4. Definitions

TermMeaning
SSC₀System suitability control. A standard peptide digest at a fixed load, used as the instrument's reference. Bypasses sample-preparation variability.
QC AProcess control. A lysate carried through the full digestion and Evotip workflow. Reports on the sample-preparation process.
QC BHandling control. Equivalent load to SSC₀ but handled through the Evotip workflow. Reports on LC-MS and handling, independent of digestion.
EB / PBEvotip blank / plate blank. Injections used to detect carryover.
SPDSamples per day. The Evosep chromatographic method speed (e.g. 200 SPD). Retention times and intensities differ materially between SPD methods, so each has its own baseline.
Gold standard / baselineThe per-peptide reference values computed from a selected set of SSC₀ runs on one instrument at one SPD. Also called the local optimum.
Digest efficiencyRatio of the fully cleaved peptide to the sum of cleaved and miss-cleaved forms, expressed as a percentage.
idotpIsotope dot product. Agreement between the observed and theoretical isotope pattern. Confidence that the correct precursor was measured.
dotpLibrary dot product. Agreement between observed fragment intensities and a spectral library.
PayloadThe structured result file the agent writes for one run. See Annex 3.
SpoolThe on-disk queue of payloads awaiting upload, and the record of those already sent.
Part A

Installation and commissioning

Performed once, by a field service engineer. Approximately 2–3 hours excluding the SSC₀ run series.

A1. Site and IT prerequisites

Confirm all of the following before travelling to site. Several require IT involvement and cannot be resolved on the day.

RequirementDetail
Operating systemWindows 10 or 11, 64-bit. The instrument's own acquisition PC is the normal host.
Disk space2 GB free on the system drive. Results are small (~25 KB per run) but Skyline needs working space during extraction.
SkylineSkyline or Skyline-daily installed, including SkylineCmd.exe. The agent locates it automatically; confirm with mdqc doctor.
Vendor readersThe vendor libraries Skyline needs to read this instrument's raw format must already be present — normally satisfied on an acquisition PC.
PermissionsRead access to the acquisition folder; write access to C:\ProgramData\MassDynamics\QC\. Local administrator rights are required for installation only.
Network (cloud only)Outbound HTTPS (443) to the Mass Dynamics endpoint. No inbound connection is ever required. See §C5 for the IT summary.
Account (cloud only)A Mass Dynamics account for the customer's organisation, with an API token available.
Check first

Instrument PCs are commonly on a restricted network segment with no outbound internet. Establish this with IT in advance. If egress cannot be granted, the agent still runs — install local-only and revisit later.

A2. Install the agent

Two routes. Use the installer unless the site has a working Python environment and a preference for it.

Route 1 — Windows installer (recommended)

  1. Obtain mdqc-setup-v0.5.8.exe from Mass Dynamics.
  2. Run it as administrator and accept the defaults. The installer registers the agent as a Windows service so it starts automatically with the PC.
  3. Confirm the service MassDynamicsQC appears in Services and is set to start automatically.

Route 2 — Python environment

pip install --user --upgrade "git+https://github.com/webwebb56/mdqc-py.git"

Then confirm:

python -m mdqc version
Verify before continuing

Run python -m mdqc doctor. It checks the Skyline installation, vendor readers, templates and — if configured — cloud connectivity. Resolve anything it reports before proceeding.

A3. Configure the instrument and watch folder

On first run the agent opens a setup wizard in the browser. If it does not open automatically, the address is printed to the console at startup.

  1. Instrument vendor — select the manufacturer. This determines the file pattern and how the agent decides an acquisition is complete.
  2. Instrument ID and watch path — give the instrument a stable, unique name. This identifies it on the platform and keys its baseline, so choose carefully: changing it later orphans the instrument's history. Set the watch path to the acquisition output folder.
  3. Skyline — confirm the detected SkylineCmd.exe path.
  4. Skyline template — see §A4.
  5. Output mode — local-only, or cloud upload. Choose local-only for now; §A8 connects the cloud once extraction is verified.
Watch path

Point at the folder the instrument actually writes to, not a synchronised copy or network mirror. The agent needs to observe the file growing and then settling in order to know when acquisition has finished.

A4. Skyline method and report

Two files govern extraction, both in C:\ProgramData\MassDynamics\QC\methods\:

FileRole
QC_Method.skyThe Skyline document defining the target peptides and transitions.
MD_QC_Report.skyrThe report definition selecting which columns are exported.

To use a site-specific report, set report_skyr_path in the configuration (Annex 1) rather than renaming files. The agent reads the report name from inside the .skyr, so the filename does not need to match.

Common failure

If the Skyline template is opened in the Skyline GUI and saved with results attached, those embedded replicates travel with the file. The agent strips them automatically at extraction time, but a template distributed with results embedded is much larger and slower to copy. Distribute templates saved without results.

A5. Confirm the file-naming convention

The agent determines what a run is from its filename. This is a hard requirement, not a convenience.

Requirement

Every QC injection filename must contain a control-type marker (SSC0, QCA, QCB) and, where more than one chromatographic method is in use, an SPD marker (200SPD). A file with no recognisable control-type marker is classified as a sample and skipped silently — no result, no error.

Full specification in Annex 2. To verify against real filenames before relying on them:

python -m mdqc classify "SSC0_2026-07-24_200spd_k562_S1-B1.d"

Check the reported control type, SPD and confidence. Repeat for one example of each QC type the site will run. Record the results in Annex 5.

A6. Peptide classes

Peptide classes tell the agent what each target is measuring, so that different peptides are rolled up differently. Configure them to match the Protein column values in the site's Skyline method — see Annex 1.

The most important is the miss-cleavage pair, which drives the digest-efficiency figure. It is excluded from target recovery, because the miss-cleaved form is often near the limit of quantitation and counting it would depress recovery artificially.

A7. Single-file verification

A pass/fail gate. Do not continue until this succeeds.

  1. Copy a single previously acquired QC raw file into the watch folder.
  2. Wait approximately 90 seconds — a 60 second stability window plus extraction time. Large files take longer.
  3. Open the agent's Dashboard. The run should appear in recent activity with a target count such as 8/8.
  4. Confirm a result file has appeared in C:\ProgramData\MassDynamics\QC\spool\completed\.
If targets read 0/8

The Skyline method is not matching the acquisition. Open the template in the Skyline GUI, import the same raw file manually and confirm peaks are found there. If they are not, the method or its libraries do not correspond to the acquisition method — for example, libraries built for a different SPD.

A8. Connect to Mass Dynamics

Skip this section for a local-only installation.

Do this in order

Set the retention limit before entering the API token. Connecting the cloud changes how long results are kept locally, and a low limit carried over from an earlier installation will begin deleting results as soon as the token is saved.

  1. Open Settings → Payload retention. Set Keep newest to at least 200, or higher than the largest number of runs expected in a single night. Save.
  2. Obtain the API token from the customer's Mass Dynamics account (Account Details).
  3. Open Settings → Cloud. Select the environment — Production for customer installations. Paste the token. Save.
  4. Restart the agent. A restart is required: the upload component reads its configuration once at startup.
  5. Confirm upload by dropping a test file and checking that the result moves from spool\pending\ to spool\completed\, and appears on the platform.
If the network is unavailable

Results queue in spool\pending\ and upload automatically when connectivity returns. Nothing is lost and no operator action is needed.

A9. Record the gold-standard baseline

This step establishes the reference every later run is judged against. It is the core of commissioning.

  1. Acquire the SSC₀ series. Run 15–20 SSC₀ injections at the SPD method the site will use for routine QC. Where more than one SPD will be monitored, repeat for each — baselines are per instrument and per SPD.
  2. Let the agent process them. Each is indexed automatically as it completes.
  3. Open the Gold standards page in the agent interface and select the SPD tab.
  4. Review the runs. Each row is one SSC₀ run; columns are the target peptides. Cells are shaded where a value deviates from the current selection, so an outlier stands out.
  5. Select the representative runs. Tick those that should define the reference. The first injection of a series is frequently excluded — a column that has not fully equilibrated shows shifted retention times and depressed areas.
  6. Check the resulting baseline. The lower table shows the per-peptide median and CV% across the selected runs. A low CV means the chosen runs agree closely. Investigate before saving if CV% is above about 10% for the recovery peptides.
  7. Save. Give the baseline a label recording why it was made — for example Install 2026-08-04. Saving activates it immediately for subsequent runs at that SPD.
Why the selection is manual

An engineer commissioning an instrument knows which runs were affected by equilibration, a bubble, or an intentional adjustment. Automatic selection cannot know this. The CV% column exists to make the judgement evidence-based rather than a guess.

A10. Commissioning acceptance

Complete Annex 5 with the customer present. Every item must pass before handover. Walk the customer through Part B, in particular §B3 and §B7.

Part B

Routine operation

Laboratory staff. No daily action is required beyond reviewing results.

B1. What happens automatically

Once commissioned the agent requires no intervention. Every QC injection is detected, extracted, compared against the baseline, and — where configured — uploaded, within a few minutes of acquisition completing. The agent starts with the PC.

Your role is to review the results and act when they indicate a problem.

B2. The agent interface

Open the agent's web interface from the system tray icon. It is served locally and is not reachable from other machines.

PageUse
DashboardService status, queue counts, recent activity. The everyday view.
Gold standardsReview SSC₀ runs and the active baseline; re-baseline (§B7).
SettingsConfiguration. Changing cloud settings requires a restart.
DiagnosticsThe same checks as mdqc doctor, in the browser.
FailedRuns that could not be extracted, with the reason. Retry from here.
LogsRecent agent log, for support.

Healthy looks like: status Running; pending count at or near zero; failed count zero; recent activity showing each expected QC injection with full target recovery.

B3. The Mass Dynamics platform

The platform is where results are reviewed over time and across instruments.

  1. Sign in to your organisation's Mass Dynamics account.
  2. Open the workspace containing the QC modules.
  3. Add your instrument to each module's filter. Open the module's details panel, select the instrument, and save changes.
Most common cause of "my data isn't showing"

A module displays only the instruments selected in its filter. A newly commissioned instrument is not selected by default, so its results are uploaded and stored but not displayed until it is added. If data is missing from a view, check this before anything else.

B4. Reading the QC views

ViewShowsUse it to
Traffic light / scorecardRecent runs against metrics, coloured by how far each sits from the referenceAnswer "is anything wrong right now?" at a glance
Longitudinal trackingOne metric over time, per peptide or aggregatedDistinguish a gradual drift from a single bad run
Ratio panelsQC A and QC B relative to SSC₀Separate an LC-MS problem from a sample-preparation problem

The ratio panels carry most of the diagnostic value. QC B and SSC₀ receive equivalent loads and both bypass digestion, so QC B relative to SSC₀ reports on LC-MS health. QC A additionally carries digestion, so QC A falling while QC B holds steady points at sample preparation rather than the instrument.

B5. Interpreting a result

All comparisons are relative to the SSC₀ baseline for that instrument and SPD.

Provisional values

The thresholds below are a first draft derived from a single instrument. They are configurable and expected to be refined as data accumulates across platforms. Treat them as guidance for investigation, not as an acceptance specification. Current defaults and their origin are in Annex 4.

Is the measurement trustworthy?

Before treating a poor result as an instrument problem, establish that the correct peak was measured. A wrongly integrated peak and a genuine performance drop look identical if only peak area is considered.

SignatureInterpretation
Retention time within 2% of baseline, dot products within 5%Correct target. Any area change is real.
Retention time beyond 2% together with depressed dot products or a large area changeProbably the wrong peak. Flagged as an extraction problem, not a performance problem.
Retention time shifted, everything else normalA chromatographic shift affecting all peptides — check for a column or gradient change rather than a single-peptide issue.
Dot products alone are not sufficient

A wrongly extracted peak has been observed with an isotope dot product of 0.92 — a value that looks healthy. Retention time is the more reliable discriminator, which is why the flag requires a combination of signals.

Is the signal where it should be?

Peak area vs SSC₀Indicates
Within about 10%Normal.
About 10% belowPossibly as much as a 25% reduction in material reaching the column. The response is buffered — a modest area change can reflect a much larger loading change.
About 25% belowPossibly as much as a 50% reduction.
Replicates from one preparation run varying by more than 10%Inconsistent Evotip loading rather than an instrument problem.

B6. Escalation

ObservationLikely domainAction
QC B and SSC₀ both down; QC A down proportionallyLC-MSCheck column, emitter, spray stability. Evosep support if unresolved.
QC A down; QC B and SSC₀ steadySample preparationReview the digestion and Evotip loading for that batch. Check digest efficiency.
Retention times drifting across all peptidesChromatographyCheck column age and pressure. Re-baseline after any column change (§B7).
One peptide flagged as an extraction problem, others normalData processingNot an instrument fault. Report to Mass Dynamics — the method may need adjustment.
Replicate variability high within one preparation runSample preparationReview Lupo loading for that plate.
Runs not appearing at allConfiguration§C1. Check filenames first (§A5).

B7. Re-baselining

The baseline describes the instrument as it was when recorded. After a deliberate change, it no longer does, and comparisons become misleading.

Re-baseline after: a column change; a major service or clean; a change of chromatographic method; any intentional configuration change expected to alter performance.

Do not re-baseline to make a warning disappear. If performance has degraded unintentionally, a new baseline conceals the problem — the instrument is then measured against its own degraded state.

  1. Complete the change and allow the system to stabilise.
  2. Run a fresh SSC₀ series — 15–20 injections at the relevant SPD.
  3. Open Gold standards, select the new runs, and save with a label recording the reason, for example After column change 2026-09-12.

Previous baselines are retained. Runs record which baseline they were measured against, so history remains interpretable across a re-baseline.

Part C

Maintenance, troubleshooting and reference

Laboratory staff, service engineers and IT.

C1. Failure modes

Failure modePossible causeResolution
No results produced; log repeats SkylineCmd.exe not found Skyline not installed in a standard location, and no explicit path configured Install Skyline to its default location, or set [skyline] path in the configuration. Verify with mdqc doctor.
Some QC injections never appear Filenames lack a recognisable control-type marker, so the runs are classified as samples and skipped Verify with mdqc classify (§A5). Correct the naming convention, or add a matching rule to the configuration.
0/8 targets found on every run Skyline method does not match the acquisition method Import a raw file into the template manually in Skyline. If no peaks are found there, the method or its libraries are wrong for this acquisition — commonly libraries for a different SPD.
Report error naming a report that does not exist The configured .skyr is missing Restore the report to the methods folder, or correct report_skyr_path.
Warning that a column override was not found A column mapping in the configuration refers to a column that a newer report no longer contains Remove the stale override. The built-in mapping resolves current column names automatically.
Skyline error: file in use by another process Concurrent extractions contending for the chromatogram cache Handled automatically by per-extraction temporary directories. If it persists, end any stuck SkylineCmd.exe processes and restart the agent.
Only the most recent results remain on disk Retention limit set too low, or carried over from an earlier installation Settings → Payload retention. Raise Keep newest above the busiest expected night. See §A8.
Results stay in spool\pending\ No network route to the platform, or an invalid token Confirm outbound HTTPS. Re-enter the token and restart. Queued results upload automatically once connectivity returns — nothing is lost.
Results upload but do not appear on the platform The instrument is not selected in the module's filter Add it (§B3).
Cloud settings saved but nothing uploads The agent was not restarted Restart. Cloud configuration is read once at startup; the interface displays a reminder when a restart is required.
No comparison against the baseline in results No baseline saved for that instrument and SPD, or the SPD could not be read from the filename Confirm the SPD marker is present (Annex 2), then record a baseline (§A9).
A peptide is persistently flagged as an extraction problem The wrong peak is being integrated, commonly for a low-intensity target Not an instrument fault. Send a support bundle (§C3) — the method may need adjustment.

C4. Upgrading

Configuration, baselines and stored results are preserved across upgrades.

pip install --user --upgrade "git+https://github.com/webwebb56/mdqc-py.git"

Or run the newer installer over the existing installation. Restart the agent afterwards and confirm the version on the Dashboard. After any upgrade, verify that a run completes end to end before leaving the system unattended.

C5. Data handling and IT review

Summary for an IT or information-security reviewer.

QuestionAnswer
What leaves the instrument PC?Derived QC measurements only — peptide retention times, peak areas, quality scores and run metadata. Raw data files are never transmitted. A result file is approximately 25 KB.
Where does it go?The Mass Dynamics platform endpoint configured at installation, over HTTPS.
How is it authenticated?A bearer token issued to the customer's own account, stored in config.toml on the instrument PC.
Inbound connections?None. The agent only makes outbound requests. Its interface is bound to the local loopback address and is not reachable from the network.
What if the network is unavailable?Results queue locally and upload when connectivity returns.
Can it run with no network at all?Yes. Omit the cloud configuration. All monitoring works locally; only cross-instrument and longitudinal review on the platform is unavailable.
What is retained locally?Results under spool\, bounded by count or age (Annex 1), and baselines under gold_standards\.
Third-party components?Skyline (MacCoss Lab, University of Washington) performs extraction locally. The agent is open source under the MIT licence.

C6. Uninstall

  1. Stop the agent — Services, or close the foreground window.
  2. Remove via Add/Remove Programs, or pip uninstall mdqc.
  3. C:\ProgramData\MassDynamics\QC\ is left in place. Retain it if results or baselines are still needed; delete it for a complete removal.

Annex 2 — File-naming specification

Markers may appear anywhere in the filename and are matched case-insensitively. Each must be delimited by the start or end of the name, or by _, -, a space or a full stop. The vendor extension is ignored.

MarkerAccepted formsResult
Control typeSSC0, SSCClassified SSC₀
QCA, QC_A, QC-AClassified QC A
QCB, QC_B, QC-BClassified QC B
BLANK, BLKClassified blank
SPD200SPD, 200spd, 200-SPDSelects the matching baseline. Required where more than one method is used.
Dilution75perc, 75pct, 75%Recorded for dilution studies. Optional.
WellA1 … H12Recorded. Raises classification confidence.

Worked example

QCB_75perc_2026-07-24_ss_50ng_Manual_200spd_k562_S1-F8_1.d
 │    │                              │            │
 │    │                              │            └─ well F8
 │    │                              └─ 200 SPD
 │    └─ 75% dilution
 └─ QC B
Precedence and pitfalls

Where several control-type markers are present, the order of precedence is SSC₀, QC A, QC B, blank. A marker embedded in a longer word is not matched — 200spdx does not register as an SPD. Custom rules in the configuration take precedence over all built-in markers.

Annex 3 — Payload reference

One JSON file per run. Principal sections:

SectionContents
runFilename, acquisition time, instrument, vendor, control type, SPD, dilution, well, plate, classification confidence.
extractionBackend and version, template, duration, status, any error message.
target_metricsOne entry per peptide: sequence, retention time, peak area, mass error, dot products, peak shape, peptide class.
run_metricsTarget recovery, median retention-time shift, median mass error, digest efficiency.
baseline_contextWhich baseline this run was measured against, and a copy of its reference values. Empty where no baseline is active.
comparison_metricsRatios and deviations against that baseline, per peptide and per run, plus the thresholds applied.

Full field-level schema is maintained separately for platform integration.

Annex 4 — Default thresholds and provenance

Provisional

These derive from a single dilution series on one instrument (timsTOF HT, July 2026): QC B at 100%, 75% and 50% across 200, 300 and 500 SPD with eight replicates each, plus sixteen SSC₀ at 200 SPD. The same series is being repeated on further platforms. Values are configurable and expected to change. They are not an instrument acceptance specification.

SettingDefaultBasis
rt_deviation_pct_max2.0Retention time varies well under 1% across a batch absent chromatographic change, making it the most reliable indicator of a wrongly integrated peak.
dot_product_deviation_pct_max5.0Expected agreement for a correctly identified target.
dot_product_deviation_pct_suspect10.0Together with retention-time deviation, indicates the wrong peak.
peak_area_deviation_pct_suspect30.0Large area change accompanying retention-time deviation.
peak_area_deviation_pct_warn10.0Approximately a 25% reduction in material reaching the column.
peak_area_deviation_pct_fail25.0Approximately a 50% reduction.
Known boundary

Against the source dataset, the 75% condition produced a median deviation of −9.5%, marginally inside the 10% warning threshold. A value nearer 8% would capture that condition. Retained at 10% pending data from further platforms, and recorded here so the limitation is visible to anyone tuning these values.
